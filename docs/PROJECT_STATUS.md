## Подтверждённые риски и блокеры

- PostgreSQL **18.6** в production; изолированные автоматические тесты
  на PostgreSQL **18** пройдены, в том числе backup/restore и
  точный SQL миграции. Совместимость с **реальной копией production**
  и восстановление её данных ещё не подтверждены.
- **Render Free PostgreSQL не поддерживает встроенные backup или PITR**:
  https://render.com/docs/free и https://render.com/docs/postgresql-backups.
  Production pg_dump вне Render **не сделан**. Без защищённой локальной
  резервной копии выпуск заблокирован. До 19 ноября 2026 нужно решить
  судьбу базы: после истечения доступ закрывается, спустя 14 дней grace
  данные могут быть удалены.
- Старое приложение не понимает `retired` и выбранные `weekdays`.
  Кодовый откат после реального переноса расписания небезопасен без
  совместимого хотфикса/заморозки изменений. Колонки не удалять.
- Render Postgres `ipAllowList` в конфигурации содержит `0.0.0.0/0`:
  внешняя сетевая поверхность открыта для соединений с аутентификацией.
  База показывает `ssl=on`. Ограничение публичного доступа требуется
  отдельно спланировать, чтобы не нарушить подключение текущего бота;
  ни один сетевой параметр сейчас не менялся.
- Render production logs: 23 октября два примера старого wake callback 400;
  веточное исправление ещё не опубликовано. Отдельно измерить задержку API
  `/mini/api` на холодном старте.
- Существующий бот имеет единственный webhook. Нельзя направить его сразу на
  два независимых backend. Проверка PR на том же боте требует согласованного
  временного production переключения после backup — **не выполнять сейчас**.

### Не достигнуто / важно для безопасного выпуска

1. **Пиксельная идентичность всему утверждённому HTML не подтверждена.**
   Автотесты проверяют мобильный layout, основные сценарии, но не заменяют
   ручного сравнения всех экранов и Telegram Android WebView.
2. **Динамика массы тела** пока не строится: production сохраняет лишь текущее
   измерение в `profile_metrics`, исторического ряда нет. **График рабочего
   веса теперь реализован** в последующем этапе по реальным завершённым
   подходам, через отдельный защищённый read-only API. Без записей — пустое
   состояние; график массы тела не подменять расчётной историей.
3. **FatSecret/Garmin** не синхронизируются автоматически. Форма анализа реального
   отчёта сохранена; результат анализа не выдается за синхронизацию дневника.
4. **Production backup/restore:** нет подтверждённой резервной копии текущего
   пользовательского PostgreSQL. Тестовый PG18 `pg_dump/pg_restore` выполнен,
   но не подтверждает восстановление production-копии.
5. **Откат старого планировщика** после `weekdays/retired` нельзя считать
   безопасным без отдельного совместимого hotfix.
6. **Финальный Android приёмочный прогон и одобрение владельца** не проводились.
   Webhook рабочего бота нельзя одновременно использовать двумя backend.
7. Бесплатная production PostgreSQL по Render имеет `expiresAt` **19.11.2026**.

**Гейт:** не объединять PR в `main`, не запускать Render, не менять
production БД, webhook или токен. Следующий технический этап после
визуального review — согласованное read-only резервное копирование
production и репетиция восстановления отдельно; затем проверка Android
