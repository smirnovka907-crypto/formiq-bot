# FORMIQ: отдельный запуск для Android / Telegram

Основа приложения — проверенный PR №15, коммит
`f2f6009a2804c159eb64846575e133966bb3c8d9`. Файлы запуска добавлены в ту же
ветку `fix/v5-native-onboarding-fullscreen-20261023`. `main`, production Blueprint,
production PostgreSQL и рабочий Telegram-бот для этого запуска не используются.

Этот документ описывает подготовленный запуск. Наличие файла в GitHub не означает,
что сервис уже имеет статус Live или проверен в настоящем Telegram на Android.

## 1. Отдельный Telegram-бот

1. В Telegram откройте официальный `@BotFather` и выполните `/newbot`.
2. Задайте отдельные имя и username, например с суффиксом `test_bot`.
   Username рабочего бота `formiqcoachbot` не подходит.
3. Сохраните токен нового бота непосредственно в Render при создании тестового
   Blueprint. Не добавляйте токен в GitHub, YAML, отчёты или сообщения чата.
4. Запомните username: он потребуется как `FORMIQ_TEST_BOT_USERNAME`.

Команда `/newapp` и изменение настроек рабочего бота не нужны. После запуска
существующая кнопка FormIQ в приветствии нового бота откроет Mini App с настоящим
подписанным Telegram `initData`.

## 2. Workspace и стоимость

Пользователь подтвердил `Kirill's workspace` (`tea-dbbqvfm1egvs73b0sokg`).
Проверка метаданных обнаружила в нём production `formiq-bot` на Free web и
`formiq-db` на Free PostgreSQL. Эти ресурсы не изменялись; production deploy
`11551f4305212236ee312b4e970eeb4f040c76a9` имеет статус Live.

Для запуска **в подтверждённом Kirill's workspace** подготовлен отдельный файл
`render.android-test.kirill.yaml`: web `0.5c-512mb` и PostgreSQL `0.1c-256mb`,
ровно 1 GB, автоматическое увеличение диска выключено. Оценка compute составляет
около $13 в месяц ($7 web + $6 PostgreSQL); учёт 1 GB и возможные дополнительные
платежи за storage/usage нужно сверить с итоговым расчётом в Render Dashboard.
Платные ресурсы не созданы: требуется отдельное согласование расходов.

Для бесплатного варианта используйте отдельный тестовый workspace Render.
У Free web-сервисов общая квота 750 часов на workspace; её исчерпание может
приостановить другие Free web-сервисы этого workspace. Также разрешена только
одна активная Free PostgreSQL на workspace. Поэтому эту конфигурацию нельзя
без проверки применять в workspace, обслуживающем production.

Подтвердите workspace, в котором должны создаваться новые тестовые ресурсы.
Если отдельного workspace ещё нет, сначала создайте его в Render Dashboard.
Если Free недоступен, остановитесь перед созданием платных ресурсов и согласуйте
тариф/бюджет. Текущий файл намеренно не выбирает платный тариф автоматически.

Перед Apply проверьте, что Render предлагает создать ровно два новых ресурса.
Если ресурс с таким именем уже существует, не применяйте конфигурацию, пока не
проверено, что это именно ранее созданный тестовый ресурс, а не чужой или рабочий.

При первоначальном создании Render попросит заполнить:

- `TELEGRAM_BOT_TOKEN`: токен только нового тестового бота.
- `FORMIQ_TEST_BOT_USERNAME`: его username, с `@` или без него.

Другие секреты не переносите. Не подключайте production environment groups и
не восстанавливайте production backup в тестовую базу. `DATABASE_URL` и ожидаемый
host автоматически берутся из нового PostgreSQL через `fromDatabase`.
Публичное подключение к базе закрыто (`ipAllowList: []`).

Автодеплой web-сервиса и генерация preview окружений отключены. После создания
оставьте синхронизацию Blueprint ручной, чтобы новые коммиты PR не меняли
настройки теста без проверки. По необходимости запускайте только ручной deploy
последнего успешно проверенного CI коммита этой ветки.

## 4. Защита запуска

Используется `python scripts/run_android_test.py`, а не `python main.py`.
До создания таблиц, обработки очереди, изменения профиля бота или webhook
запуск проверяет:

- `FORMIQ_ENV=android-test` и имя отдельного тестового сервиса;
- собственный HTTPS URL Render, отличный от production;
- совпадение host и имени `DATABASE_URL` с параметрами новой тестовой базы;
- отсутствие ключей Yandex, Google Sheets webhook и production admin ID;
- read-only `getMe`: токен принадлежит ожидаемому тестовому username,
  который отличается от рабочего `formiqcoachbot`.

Ошибочные настройки останавливают процесс до изменяющих действий. Токен и DSN
не должны попадать в сообщения об ошибках. В тестовом `/wake` ссылка ведёт
обратно в тестового бота. Сам интерфейс Aluminium v5 не заменяется.

## 5. Проверка готовности и открытие в Telegram

1. Дождитесь **Live** у нового тестового web-сервиса.
2. Откройте его фактический адрес `/android-test-info`. Он должен показать
   `android-test`, SHA развёрнутого коммита, baseline `f2f6009…`, правильный username
   и ссылку для запуска. URL сервиса берите из Render, а не угадывайте по имени.
3. Сверьте SHA с успешно завершённым GitHub Actions этой ветки.
4. Откройте выданную ссылку на Android в Telegram:

   `https://t.me/<test_bot_username>?start=android_test`

5. Нажмите **Start / Запустить**, затем существующую кнопку **FormIQ** под
   приветствием. Она должна открыть адрес нового тестового `/mini`.

Обычный браузер без Telegram не предоставляет подписанный `initData`, поэтому
сообщение «Открой из Telegram» ожидаемо. Обход авторизации и демонстрационные
истории для тестового запуска не добавлены.

При выборе бесплатного варианта web-сервис может засыпать после 15 минут простоя; пробуждение занимает
около минуты. Перед тестом дождитесь ответа `/android-test-info`, затем заново
откройте Mini App из нового бота. Не используйте постоянные keep-alive пинги.

## 6. Проверка на Android

Используйте вымышленные тестовые показатели, а не данные из production.

1. Первый запуск: анкета появляется внутри Aluminium v5, перехода в 38.2 нет.
2. Выберите частоту 3 и Пн/Ср/Пт; несовпадение числа дней должно мешать сохранению.
3. Сохраните анкету. Закройте Mini App и откройте заново; дни должны восстановиться.
4. В профиле измените дни и частоту; проверьте четырёхнедельный план внутри
   «Тренировок». При смене текущей недели защищённые старые слоты не дублируются.
5. Перенесите одно будущее занятие вручную, измените дни ещё раз и проверьте перенос.
6. Начните тренировку, запишите подход, повторения и вес, завершите тренировку.
7. Запишите кардио и проверьте обе записи в «Прогрессе» и подробностях истории.
8. Снова измените расписание: завершённая тренировка, подходы и вес сохраняются.
9. Проверьте fullscreen, прокрутку, клавиатуру и селектор на ширинах около 360/393 px.
10. Внизу ровно три вкладки: **Тренировки / Питание / Прогресс**.

Ограничения здоровья можно выбрать вручную в анкете. Ключи внешнего ИИ намеренно
не подключены: разбор текста через Yandex и анализ отчётов питания в этот
изолированный запуск не включены. Это не мешает перечисленным сценариям.

Реальный Android WebView считается проверенным только после этих действий;
успешный CI, HTTP health или настройка webhook не заменяют их.

## 7. Данные и остановка теста

При выборе бесплатного варианта PostgreSQL истекает через 30 дней и не предоставляет backups. Не храните
здесь данные, которые требуется сохранять надолго. При необходимости до
истечения срока отдельно экспортируйте только тестовую базу.

Для паузы остановите только новый тестовый сервис. Рабочий бот, production
сервис и его PostgreSQL при этом не требуют изменений. Базу и записи теста
не удаляйте автоматически. Правила отката расписания описаны отдельно в
`docs/WEEKDAY_SCHEDULE_SAFETY.md`.

## Проверка конфигурации

В CI выполняются:

```sh
python scripts/validate_android_test_blueprint.py
python scripts/validate_android_test_blueprint.py --profile kirill
python -m unittest discover -s tests -p 'test_*.py' -v
```

Первый скрипт проверяет изоляцию и актуальную публичную JSON Schema Render.
Локальный `--offline` проверяет только изоляцию и явно не выдаёт её за полную
валидацию схемы. При наличии Render CLI доступна дополнительная проверка:

```sh
render blueprints validate render.android-test.yaml
render blueprints validate render.android-test.kirill.yaml
```

Она не создаёт ресурсы. Окончательную доступность тарифов и создание ресурсов
подтверждает проверка нового Blueprint в Render Dashboard.
