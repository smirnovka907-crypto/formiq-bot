# FORMIQ — Windows: настоящая шифрованная копия PostgreSQL 18

**Статус:** инструкция и синтетические тесты. Это НЕ свидетельство созданной production-копии. Работать только на личном доверенном компьютере. Пароли, External URL и содержимое базы **не присылать в ChatGPT, Telegram, GitHub, обычную почту или журналы**.

## 1. Подготовь компьютер (один раз)

1. Установи **Python 3.12 или новее** для Windows с https://www.python.org/downloads/windows/ . Во время установки отметь добавление Python в PATH, если предложено.
2. Установи **PostgreSQL 18 для Windows** из официального каталога https://www.postgresql.org/download/windows/ . Нужны `pg_dump`, `pg_restore`, `psql`, `createdb`. Для восстановления нужна также **локальная PostgreSQL 18**, работающая только на твоём ПК (localhost). Сохрани отдельный пароль учётной записи `postgres` в менеджере паролей.
3. Открой [Draft PR #36](https://github.com/smirnovka907-crypto/formiq-bot/pull/36) → **Code → Download ZIP** для ветки `pilot/issue-35-timeweb-vps-offline-20261027`. Распакуй папку в свой профиль Windows (не в публичный/общий каталог). Не скачивай случайные сборки и не запускай скрипты с посторонних сайтов.
4. Дважды щёлкни **`scripts/FORMIQ_Backup_Windows.cmd`**. Выбери **1**, чтобы проверить Python и клиент PostgreSQL 18. Копировать команды в PowerShell не нужно.
5. Если Python сообщает об отсутствии `cryptography`, перезапусти этот же файл и выбери **5** — установится только зависимость из существующего `requirements-backup.txt`. Не передавай никому парольную фразу.

## 2. Создай зашифрованную копию Render

1. Ещё раз запусти `FORMIQ_Backup_Windows.cmd`, выбери **2**.
2. В личном кабинете **Render → formiq-db → Connect** скопируй **External Database URL**. Вставь его в скрытый запрос программы на своём ПК — **не сюда**. Программа разрешает только существующую базу Render с именем `formiq_db`.
3. Придумай уникальную парольную фразу **минимум 20 символов**, введи её дважды через скрытый запрос. Сохрани эту фразу **отдельно** в менеджере паролей. Она необходима для восстановления.
4. Дождись сообщения **`ENCRYPTED_BACKUP_CREATED_AND_FORMAT_CHECKED`**. Скрипт создаёт случайно названный `.fiqenc` в `C:\Users\<твоя_учётная_запись>\FORMIQ-private-backups\`, проверяет его аутентичность и структуру PostgreSQL и печатает **SHA256**. Только это сообщение подтверждает создание локального архива (но не восстановление).
5. Скопируй **только зашифрованный `.fiqenc`** в существующую приватную папку Google Drive **«05_Резервные копии БД»**. Никаких `.sql`, незашифрованных дампов, текстов профилей, URL или парольных фраз в облако не загружай. Сверь SHA256 у исходного и повторно скачанного файла. Для удобства выбери **6** в том же Windows-launcher и укажи путь исходного/повторно скачанного `.fiqenc`: он напечатает SHA256 без открытия содержимого и без пароля. Без проверенного содержимого папки «backup есть» не заявлять.

## 3. Проверь восстановление на этом же ПК

1. Убедись, что локальная PostgreSQL 18 запущена и слушает **127.0.0.1**, а не открыта в интернет. **Никогда** не указывай Render URL как цель восстановления.
2. Запусти `FORMIQ_Backup_Windows.cmd`, выбери **4**. Скрипт попытается **создать новую** пустую локальную БД `formiq_restore`. PostgreSQL может попросить пароль локального пользователя `postgres`. **Если база уже существует, скрипт остановится, ничего не удаляя и не перезаписывая**.
3. Выбери архив (Enter для самого нового), введи сохранённую парольную фразу и скрыто укажи **только локальный URL** вида `postgresql://postgres:<локальный_пароль>@127.0.0.1:5432/formiq_restore` (этот пример — шаблон, не реальные реквизиты). URL не печатается и не записывается в файл.
4. После успешного `pg_restore` программа отдельно попросит **Render External URL** и локальный URL ещё раз, чтобы выполнить read-only сверку. Она сравнит список таблиц, число записей в каждой, PK/FK и прочие ограничения, последовательности ID и отношения тренировок/питания. На экране появится **`LOCAL_RESTORE_RECONCILED`**, если показатели совпали.
5. Если источник Render изменился между созданием копии и сверкой, возможны расхождения. **Не игнорируй ошибку NO-GO**: это не повод удалять данные. Для переезда потребуется отдельный финальный дамп при временно остановленной записи. Если восстановление остановилось до сверки, настоящая копия всё ещё может быть пригодной, но **успешное восстановление не подтверждено**.
6. Локальная `formiq_restore` содержит реальные приватные данные: не делай скриншоты строк/паролей, не публикуй результаты, не открывай к ней внешнее подключение. Не удаляй исходные копии до подтверждённого восстановления.

## 4. Что можно сообщить в «FORMIQ | Разработка 9»

Разрешено сообщить **только**:
- «`ENCRYPTED_BACKUP_CREATED_AND_FORMAT_CHECKED` — да/нет».
- «`LOCAL_RESTORE_RECONCILED` — да/нет».
- «Приватный Google Drive `.fiqenc` загружен и SHA256 совпадает — да/нет».

**Нельзя присылать:** парольную фразу, URL Render, пароль PostgreSQL, файл незашифрованного дампа, реальные строки профилей или описание здоровья.

## 5. Если что-то не запускается

- «Python 3.12+ required» → установить Python из официального сайта.
- «PostgreSQL 18 client missing» → установить PostgreSQL 18, затем ещё раз выбор 1.
- «cryptography» → выбор 5, затем 2.
- «Local database creation refused» → проверить, что служба PostgreSQL 18 запущена, пароль локального postgres верен, либо существующая `formiq_restore` не пуста. **Не удалять старую базу автоматически**.
- «AUDIT_NO_GO» → возможное изменение production записей после дампа, ошибка прав либо несоответствие. Повторять только на доверенном ПК и **ничего не удалять**.
- Вся программа выдаёт ошибки без печати секретов. Не пересылай диагностические логи с адресами, паролями или личными данными.

**Выпуск/перенос всё ещё запрещён** без отдельного разрешения, юридической проверки обработки медицинских данных и подтверждённой изолированной restore-копии. Истечение Render PostgreSQL Free — **19 ноября 2026, 22:50 МСК**.
