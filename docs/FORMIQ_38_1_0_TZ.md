# FORMIQ 38.1.0 — единое техническое задание (на согласование)
Дата: 2026-10-22. Статус: DRAFT, не является разрешением на production release.

## Миссия
FORMIQ — персональный AI Coach в Telegram: тренировки, питание, восстановление и прогресс на основе собственной истории и подключённых источников. Визуальные ориентиры — спокойная элегантность iOS и простота решений Tesla, без копирования чужой айдентики. Принцип: меньше действий, больше ясности и надёжности.

- Production: GitHub smirnovka907-crypto/formiq-bot, main @ 420ed290ac535f00385b0c50dedfde41b9ca0858; Render formiq-bot Live 38.0.0; PostgreSQL с историей пользователей.
- Текущий main.py: VERSION 38.0.0; три тарифа start/comfort/max; AI/тренировки/план/история/питание/отзывы уже имеют код. Существующие функции сохраняем.
- Замечания после 38.0.0: несогласованный перегруженный дизайн, разные шрифты и масштабы, белая нечитаемая «Начать», медленные «Сохранить»/«Начать», избыточные медицинские поля, ИИ задаёт уточнение без ввода, дублирующая синяя Telegram menu-кнопка, неудачный логотип/стартовый баннер, скрытый/перегруженный блок отзывов.

## P0. Основа UX: один стандарт
1. Шрифт: системный стек San Francisco (при наличии), -apple-system, BlinkMacSystemFont, Roboto, Arial, sans-serif. Размер: 24 px заголовок страницы, 20 px заголовок раздела, 16 px весь основной текст и текст CTA, 14 px пояснение, 12–13 px метаданные. Не использовать разные семейства на разных экранах.
2. Три темы: light/dark/system; system реально следует Telegram WebApp.colorScheme и prefers-color-scheme; выбор сохраняется; никаких принудительных dark-override.
3. Единая сетка: отступы 8/12/16/24px, скругления 12/16/20px по назначению, одинаковые кнопки 48–52px в высоту, hit-area минимум 44px.
4. Контраст WCAG AA: 4.5:1 для обычного текста, 3:1 для крупного и UI; основная CTA всегда контрастна и явно включена/выключена.
5. Удалить крупные светящиеся сферы, декоративные перепады толщин, дублирующие карточки и ненужные эффекты; анимация 120–200мс, reduce-motion.
6. Логотип/приветствие выпускаются только после утверждения конкретного варианта; проверить квадратное аватарное и широкое Telegram crop-оформление.

## P0. Главная страница и навигация
Основная навигация: Сегодня | План | Прогресс. Главная показывает: название ближайшей тренировки, длительность, одна CTA «Начать» (или «Продолжить»), краткое резюме прогресса, компактную точку входа к AI, один видимый пункт «Отзывы и предложения». Настройки справа. Без тарифов и длинных рекламных блоков на главной. Повторный запуск минует анкету. AI остается доступен, но не увеличивает количество основных вкладок.

## P0. Скорость, устойчивость
Инструментировать время по шагам: tap -> immediate UI -> API -> DB -> render; найти корневую причину задержек, не подменять оптимизацию спиннерами. Immediate feedback <100ms, целевой p95 основных операций <2s на нормальной сети (подтвердить замерами). Защитить от двойного клика, дублирующих запросов и записей; retry безопасен/idempotent. В случае ошибки — явный статус, пользовательский ввод сохраняется, без ложного «Сохранено».

## P0. Анкета и здоровье
Одна короткая анкета: возраст/18+, рост, вес, цель, опыт, дни/неделя, время, условия тренировок. Пульс в покое не запрашивать. Ограничения: произвольный текст и отдельное согласие на Yandex AI; результат ИИ отобразить, уточняющий вопрос всегда сопровождается полем ответа, пользователь может править перед сохранением. Боль 0–10, давность и прочие подробности — только по необходимости, не как обязательные блоки. Существующие барьеры безопасности, согласия и отказ от медицинской диагностики сохранить; не допускать предложения противопоказанных движений.

## P0. Telegram-оболочка
Внизу только основные действия FormIQ и Разбудить. Выключить лишнюю конфигурацию синей Menu WebApp кнопки если Telegram Bot API позволяет; системные кнопки клиента Telegram не скрываем недокументированно. Стартовое изображение минималистичное, компактное, логотип без артефактов. Не потерять доступность Mini App.

## P0. Два тарифных варианта
Текущие три уровня убрать из нового UI, при этом сохранить действующие права/историю. Ранее подтверждались 14 дней пробного периода, затем полный доступ 990 ₽/мес, без привязки карты на входе и без автопродления; одновременно обсуждались ровно два варианта тарифов, но точная конфигурация двух платных уровней НЕ восстановлена. Не придумывать вторую цену или наполнение: до внедрения сверить исходное согласование. Не включать реальные списания и не расширять платёжную часть в 38.1.0.

## P0/P1. Garmin Connect — приоритет интеграций
Официальный Garmin Connect Developer Program (Business OAuth 2.0) либо Personal API только для собственной отладки, не для подключения пользователей продукта. Starter Business: push-only, без истории; исторические данные и ping/pull зависят от Enterprise. Разрешения пользователя и правила платформы обязательны.
Нужно: зарегистрировать приложение, получить допустимые scope/endpoints и документацию; серверные OAuth2/callback/consent, проверка происхождения push-событий по официальной схеме, очереди/повторы, маппинг Garmin userId на Telegram user_id; idempotent upsert; дата обновления; отключение/отзыв; хранение токенов шифрованно; источники и единицы измерений; обнаружение пропусков и дублей. Метрики после явных разрешений: activity, steps, resting HR, sleep, stress, Body Battery при доступности. Без API approval только изолированный адаптер и тесты, НЕ отображать кнопку «Подключено».

## P0/P1. FatSecret — приоритет интеграций
Для существующего аккаунта FatSecret использовать 3-legged OAuth 1.0a через authentication.fatsecret.com. Server-only consumer_secret и пользовательские access tokens, HTTPS callback, защита callback/state/CSRF, сверка oauth_token с pending запросом, привязка к проверенному Telegram initData. Чтение food entries v2/date, нормализация калорий/белка/жиров/углеводов, синхронизация по датам, корректная локальная временная зона и пустые дни, удалённые/исправленные записи, ограничение частоты, повторное подключение, отзыв. Не хранить пароль FatSecret. Не создавать новый параллельный дневник. Приоритет read-only.

## P1. Прогресс и объединение источников
Единый пользовательский обзор «Сегодня»: тренировка FORMIQ, показатели Garmin с меткой источника/времени, питание FatSecret. Никакой двойной суммы активности и калорий из разных провайдеров. Ручные записи имеют приоритет, если пользователь это выбрал; конфликт источников видим. Нет метрик -> спокойный пустой экран без нулей, представляющих отсутствующие данные. AI может опираться на показатели лишь при отдельном согласии, объясняет источник и неопределённость.

## P1. Отзывы и предложения
Один пункт на главной, один экран для идеи/ошибки, сохранение через существующий backend feedback и подтверждение доставки. Не плодить вторую базу пожеланий и обязательные категории.

## P1. Характер FORMIQ
Короткие, конкретные и ненавязчивые сообщения о реальном прогрессе, языке человеческой поддержки. Не выдумывать факты; никакого «мотивационного» шума после каждого касания. Возможность отключить подсказки.

## P2. Apple Health / Samsung Health
Будущие мобильные bridge-приложения с HealthKit / Samsung Health Data SDK или Android Health Connect; Telegram Mini App не получает доступ к ним напрямую. Заложить совместимую схему, не показывать неработающие коннекторы в рабочей версии.

## Технические требования
- Источник истины: актуальный main SHA GitHub + status Render + schema PostgreSQL, затем отдельная release-ветка. Не перезаписывать несверенный код.
- Миграции только additive/reversible, резервная копия БД перед затрагивающими данные изменениями + проверенное восстановление; никогда не удалять дневник.
- Секреты и токены только в секрет-хранилище/Render Environment, не в GitHub и логах. Не публиковать данные пользователей в логах.
- API: проверять подписи Telegram initData, OAuth state и callback, scope/consent, rate limiting, input validation, права пользователя.
- Статические Python/HTML/CSS/JS проверки; тесты переходов, состояния кнопок, возврата после ошибки, мобильных разрешений; API contract tests и 429/5xx retry; DB migration/rollback rehearsal; реальные замеры задержек.
- Production release только после утверждения визуалов, пройденных тестов, совместимости хранилища и подтверждённого Render Live. Стадию написания кода не выдавать за запуск.
